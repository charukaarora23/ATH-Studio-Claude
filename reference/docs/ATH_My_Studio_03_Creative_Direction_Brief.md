# ATH My Studio: Creative direction and non-negotiables
## Design brief v0.2
10 October 2026 | Based on Charuka’s latest direction

### 1. Design intent
A clean, spacious, highly considered digital workspace that evokes writing by hand, turning to a saved page, and organising documents in files. Material familiarity should come through precision, movement, texture, and small sensory details.
The experience is contemporary and restrained. Manual/vintage qualities belong in selected details, not a blanket sepia or distressed-paper aesthetic.

### 2. Binding constraints
- Strictly follow the ATH design system when supplied.
- No invented or substituted fonts.
- No automatically introduced off-white/cream background.
- No hard offset shadows or generic “vibe-coded” visual treatments.
- No generic rounded-card dashboard as the default composition.
- No em dashes in default interface copy.
- No decorative clutter to signal creativity.
- No claim that a concept is globally unprecedented. Develop original compositions from the user’s direction and references; avoid copying another product’s expression.
- Do not assume either attached prototype palette/font set is approved.
- Do not select final visual tokens before seeing the design system.

### 3. Proposed organising idea
The file tab is navigation. The journal page is input. The finished sheet is the output. The archive preserves the artist’s work.
These objects express a continuous action, rather than appearing as disconnected decorative illustrations.
Prototype naming: My Studio / Bio / Statements / My Files. Final labels can change, but clarity takes precedence over poetic tool names.

### 4. Material restraint
| Detail | Intended role | Avoid |
|---|---|---|
| File tab | Stable navigation and document category | Tiny labels, hidden folders |
| Journal margin | Secondary prompts and notes | Excess ornamental handwriting |
| Page edge | Indicate document continuity | Heavy fake 3D stacks |
| Date/stamp mark | Honest saved status | “Verified” or quality-certification implications |
| Texture | Quiet depth in approved areas | Grain over body text |
| Cursor response | Small optional pointer feedback | Replacing the caret or hiding the normal pointer |
| Sound | Opt-in response to a material action | Continuous sound or keystroke effects |

Any custom cursor is optional, desktop-only enhancement. Native text caret, selection, focus, touch controls, and accessibility remain intact.

### 5. Design-system intake checklist
Needed before final visual implementation:
- Approved logo and wordmark.
- Font families, files/licences, weights, and type roles.
- Colour tokens and usage rules.
- Spacing, grid, radii, borders, elevation rules.
- Existing form/navigation components.
- Icon rules.
- Motion guidance, if any.
- References for file tabs, paper interaction, and desired sound/texture.

Map every component to these tokens. If a needed token is absent, document the gap and propose a specific addition instead of silently inventing one.

### 6. Composition
Give the workspace enough room to breathe. Density should increase appropriately inside large archives without forcing endless whitespace.
Home: a recognisable file system with useful recent work.
Writing: one dominant task and a readable page.
Review: text, length, and revision actions.
Archive: find and reopen, with clear labels and dates.
On mobile, preserve the sequence and character through page/label detail rather than miniature desktop objects.

### 7. Motion principles
Movement should reveal hierarchy, transition between writing and filing, or confirm a completed action.
Avoid whole-form parallax while editing, perpetual drifting backgrounds, compulsory cinematic intros, and token-by-token animation that delays reading.
Prototype durations can begin around 150–300 ms and be tuned on actual devices; these are proposed interaction timings, not brand tokens.
Reduced motion provides an equally complete static state. User input can interrupt transitions.

### 8. Sound and texture specification
Treat these as deliberate assets with documented source/licence.
Use sparse one-shot paper/file cues with default-off sound controls.
Texture must remain legible at zoom, avoid visible seams, and be tested on different pixel densities.
No audio is required to understand success/failure. No haptic promise for unsupported devices.
A sensory offline feeling does not imply offline generation or syncing.

### 9. Reference analysis method
When references arrive, annotate:
1. The precise quality to learn from.
2. Its functional role.
3. What we will reinterpret for ATH.
4. How it behaves on touch and keyboard.
5. What will not be copied.
The uploaded HTML provides workflow evidence; the uploaded Markdown provides a different proposed cinematic language. Neither replaces the new references or design system.

### 10. Approval sequence
A. Token mapping and reference annotations.
B. One tab, one journal page, one finished document, one filing transition.
C. Desktop and mobile Bio Writer journey.
D. Populated archive and returning-user state.
E. Expand into Statement Writer and other tools.

Judge each stage on brand fidelity, readability, original composition, interaction meaning, speed, and task completion.
No final UI implementation is claimed by this document. The next visual milestone depends on access to the user’s design system and file-tab references.
